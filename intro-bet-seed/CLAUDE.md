# 🎵 プロジェクト: イントロベット

## 0. このプロジェクトは何か

オリジナル楽曲のイントロを聴いて、「この曲の歌詞にどのワードが出てくるか」を予想し、
ゲーム内コインを賭け合うスマホ持ち寄り型パーティーゲーム。

- ホストが部屋を作り、参加者は自分のスマホから入室（Jackbox方式）
- イントロが流れる十数秒で、提示された6ワードにコインをベット（分散可）
- 歌詞が明かされ、当たったワードに賭けた人がコインを獲得
- 全ラウンド終了後、コイン最多のプレイヤーが勝利

**楽曲はすべてなつみの自作（Suno）**。権利がクリアなので音源をアプリ内で直接再生できる。
歌手は架空キャラクターで、それぞれ歌詞の語彙にクセがある。
**「歌手のクセを覚えるほど強くなる」ことがこのゲームの背骨。**

## 1. 開発チーム体制（自律連携モード）
Claude Code は以下の専門家チームとして自律的に連携し、修正ごとに `git add / commit / push` を自動で行うこと。

* **👑 PM**: 仕様書の遵守と「なつみの願い」の管理。
* **🛠️ Lead Engineer**: リアルタイム同期、ベット判定の正確性、Firebase、Stripe、バグゼロの徹底。
* **🎨 Creative Director**: 「脱・AI感」。歌手キャラの世界観に合った、遊び心のあるデザイン。
* **💰 運営・法務**: 決済フロー、特定商取引法に基づく表記、**賭博性の否定**（コインは換金不可）。
* **📚 Game Designer**: 倍率バランス、候補ワード生成、キャラごとの語彙設計。

**本番マージについて**: 開発ブランチでの修正が完了し動作確認（ビルド・テスト）ができたら、
都度確認を取らずに Claude Code の判断で `main` へのPRマージを行ってよい。
ただし、テストが通らない・重大な仕様変更・課金/決済まわりなど影響が大きい変更は、
念のためなつみに一声かけてからマージすること。

## 2. 絶対厳守：確定仕様

### 🎮 ゲームルール
- **プレイ人数**: 無料は2〜4人、有料は2〜10人。**課金するのはホストだけ**（参加者は常に無料）
- **ゲームの長さ**: 5曲（さくっと）/ 10曲（じっくり）を設定で選択
- **コイン**: 全員1,000コインスタート。**換金・譲渡は一切不可**（賭博性否定の根拠）
- **分散ベット可**: どのワードにいくら賭けるかは完全に個人の自由
- **ベットの可視性**: 設定で切替。**デフォルトはシークレット**（誰が何に賭けたか見えない）
- **全滅回を作らない**: 6候補のうち**必ず2〜3個は正解**（歌詞に実在するワード）

### 🎰 倍率設計（最重要・絶対に間違えないこと）

1. **倍率は「全曲コーパス基準」の出現率から計算する。歌手ごとの出現率で計算してはいけない。**
   歌手ごとに計算すると「この歌手は"海"をよく歌う」という知識が倍率に織り込まれ、
   歌手を覚えても儲からなくなる。やり込み報酬が死ぬ。

2. **候補6個は「曲を一切見ずに」辞書からティア別に抽出する。**
   堅い2 / 中間2 / 穴2（30%で穴1枠を大穴に）。
   抽出した6個のうち、その曲の歌詞に実在するものが**自動的に**正解になる。
   正解が2個未満なら STEP 1 から引き直す（平均1.9回で成立）。

3. **❌ 正解ワードを歌詞から先に抜き出して枠に詰めてはいけない。**
   この方式は Ver.0.1 で検討したが、シミュレーションで破綻が確認された。
   レアワードは「歌詞に入っている」時点で高確率に選ばれるため、
   表示時の正解率が跳ね上がり、**大穴の倍率が17.3倍→7.5倍まで落ち込む**。
   本作最大の見せ場である「大穴を当てて大逆転」が消える。

4. **❌ 正解を「各ティアに1つずつ」意図的に配分してはいけない。**
   穴枠に必ず正解があると、全員が穴だけに賭ければ必勝になり、倍率が意味を失う。

5. **倍率は素の出現率の逆数ではない。** 「正解2個以上」の引き直しがかかっているため、
   提示アルゴリズムを通したシミュレーションで**実測した正解率**から算出する。

   実測値（200,000ラウンド）: 堅い **1.5倍** / 中間 **2.5倍** / 穴 **6.2倍** / 大穴 **17.3倍**
   平均正解数 2.44個（2個64% / 3個29%）

   詳細は `docs/企画・仕様書.md` §4.3〜4.5。

### 🎤 歌手キャラクター
- すべて**架空のキャラクター**。実在歌手の**作風のオマージュ**に留める
- **絶対NG**: 実名をもじった名前 / AI音声で本人の声質を再現 / 「〇〇（実名）風」を売り文句にする
- **OK**: 「昭和のスター歌手」のような**カテゴリのパロディ**
- **レアワード・大穴ワードは1〜2キャラの専有にする**（歌手を見て穴を狙う判断を成立させるため）

### 🎼 楽曲
- **イントロは最低15秒**。**イントロに辞書ワードを聞かせてはいけない**（ベット締切前に答えが漏れる）
- Suno の2テイクを「バージョン違い」として両方登録してよいが、**全体の10〜20%に抑える**
  （多すぎると単なる記憶ゲームになる）

### 🎨 デザイン・UI
- **コンセプト**: AIっぽくない、遊び心のあるデザイン
- **ベット画面は2タップで1ベット完了**（額を選ぶ → ワードを押す）。イントロ十数秒で操作しきれること
- **デバイス対応**: スマホ表示を完璧に。PCでもレイアウトが崩れないこと

### 🔒 不正防止
- **正解情報をクライアントに送らない**。締切後にサーバー（Cloud Functions）が開示する
- **締切判定はサーバー時刻で行う**（端末時計の改ざんを無効化）
- **コインの増減計算はすべてサーバー側**。クライアントは表示のみ

## 3. 技術スタック

| レイヤ | 採用 |
|---|---|
| フロント | React 18 + TypeScript + Vite |
| 状態管理 | Zustand |
| リアルタイム同期 | Firebase Realtime Database（部屋の状態） |
| 永続データ | Firestore（ユーザー・購入履歴・戦績） |
| 認証 | Firebase Auth（匿名 + Google） |
| 音源配信 | Firebase Storage + CDN |
| 決済 | Stripe |
| ホスティング | Firebase Hosting |

**MVPでは音楽はホスト端末のスピーカーから再生する**（全員が同じ部屋にいる前提）。
各端末での同期再生は Phase 3 以降。設計はその移行を塞がないこと。

## 5. 開発の優先順位

**Phase 1（ソロプロトタイプ）が最重要マイルストーン。**
マルチプレイや課金より先に、1台で完結する1人用モードを作り、
**なつみが実際に遊んで「面白い」と判断できるかを確かめる。**
ここで面白くなければルールを作り直せる。手戻りが最小になる。

ビジュアルへの本格投資も Phase 1 のゲート通過後に行うこと。

## 6. 品質基準

**判定ミスは一発でユーザーの信頼を失う。**
「当たってたのに外れ扱いされた」はこのゲームで最悪の体験。

- 歌詞からのワード抽出は自動化するが、**必ず人の目で確認**する
- 表記ゆれ（愛/愛して、君/キミ/きみ）を確実に吸収する
- 倍率の表示と実際の払い戻しが1円たりともズレないこと
