# 改善の作業計画

毎回 `node bench.mjs` で測ってから採否を決める。数字が下がる変更は入れない。
経過の表は README.md にある。
**目標(なつみ指示・08-07): 音高F1 90%以上・鳴り出しF1 90%以上になるまで続ける。**
**方針転換(なつみ指示・08-08): サーバー(Audiveris)+手元エンジンの二段構えに移行。**
実測: きれいな画像はAudiveris+取り込み正規化(import_xml.js)が圧勝
(いつも何度でも: 音高99.3/音価95.8/鳴り出し92.6)、ぼけた写真は手元が圧勝
(mozart写真: Audiveris音高75/音価16)。アプリは両方読んで sanity(小節の埋まり具合)で
自動選択+手動切替。oemerは5分/頁+クラッシュで不採用。
サーバー: apps/score/server (Cloud Run, deploy-omr.yml)。
発見: Verovioは duration と type が食い違うと type を信じるので、
標準音価+付点に分解して書き出さないと再生リズムが崩れる(import_xml.jsは対応済み。
score.js の圧縮経路は未対応=手元エンジンの再生が楽譜表示より悪くなる一因、次の課題)。
いつも何度でも1ページ目の正解データ(itsumo_truth*.json)で回帰テスト可能:
`python3 score_xml.py 出力.musicxml itsumo`

## 鳴り出しを上げる手がかり（08-07 に onsetdiff.mjs で判明）

`node onsetdiff.mjs 曲 切り取り` で「どの小節で何拍ずれたか」が見える。
mozartぴったりの小節単位一致は 73→111/191 まで来た。効いた大技: 小節の長さを整数できっかり拍子に合わせる(37.4→42.1)、足りない時間を横位置で空いている場所に休符で入れる(42.1→46.1)。mozartぴったりの小節一致は121/191。残りの主因:
- 付点8分で始まる連なりの先頭が16分に化ける(-0.25拍の連鎖)。
  「端の音だけ多数決に逆らわせる」は失敗済み(下の表)。幽霊休符との相殺が絡む
- 左手の白抜き2分和音が「塗りの4分・8分」に化ける(ぼけで中の白が埋まる)
- m11のトリル・装飾の偽音(59が3連発など)
- m10 の加線上のラ(81)が消えた: 加線証拠の要求を0.85Sに締めた影響かも。要確認

## 次に潰す（効きそうな順・08-06夜の見立て）

0. **ジョプリン「広め」だけ全指標が5〜10点低い**
   ぴったり/ばらつきは音高76〜77%なのに広めは74%。切り取りの余白で
   何かのしきい値が外れている。diag を「広め」で比べること。
1. **符頭に癒着した♮**（ジョプリン m5/6）
   E♮の音がFに化ける（符頭の中心が記号に引っ張られて半段上がる）。
   前処理の記号消しは「白い隙間で切れる」前提なので、癒着すると効かない。
   幅1.5線間超の「符頭＋左のこぶ」を分解する処理が要る。
2. **ジョプリン m9 の減七和音**（14音ぶん、今夜の残りでは断念）
   D♮・B♮つきの4音和音。難しさが3つ重なっている:
   ・Ab と B は2度なので符頭が横にずれて描かれる（塊の分割が3音と数える）
   ・♮が2つ縦に重なって並ぶ（分割検出は入れたが、和音側と癒着していて切れない）
   ・♮自身が符頭として誤検出される
   崩すなら「符頭誤検出の除去 → 記号の癒着切り → 2度のオフセット対応」の順。
3. **付点2分の付点**（いつも何度でもの左手）
   付点4分は読めるようになった(0→7個)が、白抜きの2分に付く点はまだ。
   probe すると点は dy≈-0.55S dx≈0.9S にはっきりある。cleaned 画像での
   検査値をもう一度取り、輪の検査のどれで落ちるかを特定すること。
   なお付点の検査は「上下±0.65Sを走査しつつ、間の位置(0,±0.5S)の近くだけ通す」
   「点の縁から1画素あけて上下右だけ白を確認」の折衷が最良
   （密探索+厚い余白は鳴り出し34.0→31.1の誤検出、粗い格子は取りこぼし）。

4. **休符の再現率**（鳴り出しの主因のひとつ）
   いまも5個/ページ程度しか拾えない。ただし下手に緩めると誤検出の
   休符が小節を壊す（下の失敗表を見よ）。

## 昔の見立て（参考）

1. **ジョプリンの取りこぼし（再現率 67〜74%）**
   モーツァルトは95%なので手法の問題ではなく、紙が細かいのが効いている
   （線間12.7px、和音が黒い塊に潰れる）。二値化と解像度は振り切って
   200dpi・しきい値8が最良と分かっているので、次は符頭の探し方そのもの。
   `node diag.mjs joplin ぴったり` で重ね描きを出し、`crop.mjs` で塊の中を見る。

2. **休符を読んでいない**
   小節の途中の休符が読めないため、そこから後ろの音が前に詰まる。
   鳴り出しF1が伸びない一番の原因。4分休符・8分休符は形がはっきりしているので
   「五線の真ん中にある、縦に長くて孤立した塊」として拾えるはず。

3. **白抜きの符頭（2分・全音符）が拾えていない**
   写真がぼけると中の白が埋まり、塗りつぶしと区別できなくなる。
   モーツァルトの1音目（2分音符）がこれで短い音として読まれている。

4. **曲の途中の臨時記号（♯♭♮）**
   調号は読めるが曲中の記号はまだ。ジョプリンで ♮ が9箇所落ちている。

5. **修整エディタ（M4）**
   読み取りは78%どまりなので、人が直せることが実用の前提。
   浄書したSVGの音符をタップして上下に動かす、が最小の形。

## やってはいけないこと

- ベンチマークを通さずに「良くなったはず」で入れる
- 楽譜が欠ける切り取りを検証に混ぜる（改善が測れなくなる）
- 縦方向を間引いて処理を速くする（細い五線が丸ごと消える）

## 試して駄目だったこと（同じ道を二度通らないため）

| 試したこと | 結果 |
|---|---|
| 取り込む解像度を 250dpi・300dpi に上げる | 78.2% → 74.6%。情報は増えず、にじみだけ増える |
| 二値化の窓を 40px / 90px / 130px に | いずれも落ちた。63px（幅の1/26）が最良 |
| 二値化のしきい値を 10 以上に | 55%まで急落。線が千切れる |
| 符頭の重なり判定をゆるめる（1.05S→0.90S） | 78.2% → 75.5%。同じ符頭を二度拾う |
| 梁の本数を、見た位置の最大値で採る | 音価F1が 26.7% に落ちる。1箇所の見間違いに引っ張られる |
| 梁の本数を、見えない位置も含めて多数決 | 26.5%。梁の外側の「0本」に引っ張られる |
| 符頭の「上下の空き」を 0.55・0.65 にゆるめる | 音高F1が下がる（0.45のまま） |
| 鳴り出す拍を音価の積み上げでなく横位置から割り出す | 鳴り出しF1 33.9%→30.5%。浄書の間隔は時間に比例しない |
| 和音の翼の判定窓を外(0.72線間)へずらす | 80.2%→79.3%。近い窓のままが良い |
| 休符検出の「符頭が近いと諦める」を緩める | 鳴り出し34.1%→32.0%。偽の休符が小節を壊す |
| 符頭の中心の取り直しを平均→中央値 | 鳴り出し34.1%→32.3% |
| 小節の頭の空白から休符を推定 | 効果ゼロ。この曲集の頭休符は8分で、横位置のずれが小さすぎて見えない |
| 五線を強い順に選ぶ／弱い段を落とす | いずれも下がる（以前の版で確認済み） |
| 五線の外の符頭の「単語の中」検査を塗り符頭にも | joplin再現率-5(密な音符の左右にインクがある) |
| 梁の角の偽符頭を単純に削除(休符化しない) | 音高+1.5だが鳴り出し36.8→29.8。偽音が時間の穴埋めをしていた |
| 連なりの端の音は梁の多数決に逆らわせる(win-1採用) | 音価+1.0だが鳴り出し37.4→32.5。幽霊休符と二重に効く(小節長修正後は先頭のみで採用済み) |
| 先頭の音の梁を左側の列だけで数え直す | 55.5に暴落。最左の音の左に梁は無い |
| 先頭の音の梁を符尾の柱を貫く帯で数え直す | 68.2/46.1→67.6/45.9。にじみで帯が割れる |
| 音価を16分の格子に吸着(score.js) | 46.1→40.8。偽音が16分に膨れて時間を食う |
| 付点の上下余白を「片方だけ白」に緩める | 音価68.9→60.4。joplinで偽付点が大量発生 |
| 付点の余白の汚れを「先が白ければ細い線」と許す | 音価-1.9。まだ緩すぎる |
| 癒着♮由来の音で梁2本以上を棄てる | 音高-0.1/音価+0.1で相殺。本物も混ざる |
| 途中のヘ音記号に点間の白・左右の余白を要求 | 85.2→83.9〜84.0。本物の記号が落ちる |
| 加線の証拠に「縦に細い」を要求 | 77.9に暴落。加線は符頭と交差して太く見える |
| 白抜きの縦接ぎ(8の字)を輪の形で探して足す | 84.6〜84.9。joplinで輪の偽検出が増える |
| 先頭の音のオンステム計数(帯の途切れ繋ぎ付き) | ベンチ完全同値。効果もないが害もない→簡潔版のまま |

## 道具

```bash
node bench.mjs                    # 3つの物差しをまとめて測る
node audio.mjs                    # 音の歪み・減衰・長さ・濁りを測る
node diag.mjs 曲 切り取り          # 中で何が起きているかを覗く（重ね描きも出る）
node crop.mjs diag_bin.png x y w h 倍率   # 二値化画像の一部を拡大して見る
node look.mjs 曲 切り取り          # 読み取り結果を組み直して絵として見る
node e2e.mjs                      # アプリが通しで動くか確かめる
python3 make_truth.py             # 正解データを作り直す
```
