# 精度の物差し

改善のたびに同じ条件で測る。ここを通さない「改善」は信用しない。

```bash
node bench.mjs      # 2曲 × 3通りの切り取り方
```

## 測り方

- 紙の真の四隅（`*_corners.json`）を基準に、指の置き方のばらつきを3通り再現する。
  楽譜が欠ける切り取りを混ぜると改善が正しく測れないため、全ケースで楽譜は全部入る
- 正解は music21 コーパスの MusicXML（`*_truth.json` = 音高、`*_truthpd.json` = 音高+音価）
- 多重集合として突き合わせるので、並び順の違いに左右されない

## 経過

| 日時 | 変更 | 音高F1 | 音高+音価F1 |
|---|---|---|---|
| 08-04 | 基準（調号を読まない） | 47.2% | 23.9% |
| 08-04 | 調号の自動判別を追加 | 56.2% | 29.8% |
| 08-04 | 五線探索の感度を 0.45→0.30 | 58.1% | 31.7% |
| 08-04 | 五線をしきい値でなく極大点で見つける | 58.9% | 35.2% |
| 08-04 | **大譜表を小節線のつながりで判定・重なった段を落とす** | **60.5%** | **35.9%** |

## 分かっている弱点（次に潰す）

- 五線が 7/8 段しか取れない切り取りがある → 再現率の頭打ち
- 誤検出が多い（適合率 23〜68%）
- joplin の「広め」だけ調号判別が外れる
