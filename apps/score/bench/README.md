# 精度の物差し

改善のたびに同じ条件で測る。ここを通さない「改善」は信用しない。

```bash
node bench.mjs      # 2曲 × 3通りの切り取り方
```

## 測り方

- 紙の真の四隅（`*_corners.json`）を基準に、指の置き方のばらつきを3通り再現する。
  楽譜が欠ける切り取りを混ぜると改善が正しく測れないため、全ケースで楽譜は全部入る
- 正解は music21 コーパスの MusicXML（`*_truth.json` = 音高、`*_truthpd.json` = 音高+音価）
- 多重集合として突き合わせるので、並び順の違いに左右されない

## 鳴らしたときに元の曲と同じか（鳴り出しF1）

音高と音価が合っていても、鳴り出す時刻がずれれば別の曲に聞こえる。
実際にアプリが鳴らす MusicXML から「どの音がいつ鳴り始めるか」を取り出して測る。

| 日時 | 変更 | 鳴り出しF1 |
|---|---|---|
| 08-04 | 物差しを作った時点 | 3.1% |
| 08-04 | 小節線をシステム全体で探す | 14.6% |
| 08-04 | 先頭の複縦線を小節線と数えない | 15.8% |
| 08-04 | 半音の上げ下げを1音ずつ書き出す | 18.4% |
| 08-04 | 拍子より長くなった小節を詰める | 30.6% |
| 08-04 | **休符を読むようにした** | **30.8%** |

二値化の強さは 6〜9 が良く、10 を超えると急に落ちる（線が千切れる）。
解像度は 200dpi が最良で、250dpi・300dpi はかえって悪くなった（74.6% / 測定中止）。
窓の半径は 63px（＝幅の1/26）が最良。40px・90px・130px はいずれも落ちた。

## 音の確かめ方

```bash
node audio.mjs      # 波形を書き出して、歪みと減衰と長さを数値で見る
```

耳で判断すると分からなくなるので、必ず数値で見る。見るのは4つ。

- **歪み**: 和音が重なったとき最大値が1.0を超えていないか（超えると音が割れる）
- **減衰**: 低音ほど長く、高音ほど短く消えているか（ピアノの性質）
- **長さ**: 全音符と16分音符が、ちゃんと違う長さで鳴っているか
- **濁り**: 速い連なりで音量が積み上がっていないか（1.0倍前後なら濁っていない）

| 版 | 単音の最大 | 10音同時の最大 | 歪み | 音の長さ |
|---|---|---|---|---|
| 正弦波を重ねただけ | 0.40 | 1.19 | 45箇所 | 全部同じ |
| ピアノらしい音づくり | 0.33 | 0.61 | 0 | 全部同じ |
| **浄書エンジンの時刻から長さを取る** | **0.33** | **0.61** | **0** | **16分0.45秒／全音符1.15秒** |
