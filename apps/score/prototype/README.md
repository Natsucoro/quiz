# 楽譜カメラ — 試作版

M1（撮る・直す・見る・保存・印刷）と、移調・再生の実演を1枚のHTMLにまとめた試作。
サーバを使わず、ブラウザだけで動く。

## 動くもの

| 機能 | 実装 |
|---|---|
| 楽譜を撮る／写真から選ぶ | `<input type="file" capture="environment">` |
| 四隅を合わせてまっすぐにする | 射影変換を自前で解いて逆写像＋バイリニア補間 |
| 白黒にする | 積分画像による適応的二値化。局所のばらつきも見て、平坦な場所は紙とみなす |
| 複数ページをまとめる／並べる | — |
| 本棚に保存 | IndexedDB（**端末内のみ。外に送らない**） |
| スマホで見る | — |
| 紙に印刷 | `@media print` で A4 に割り付け → `window.print()` → AirPrint / Mopria |
| キーを変える | 事前に浄書した25段階（−12〜+12半音）を切り替え。調号も書き換わる |
| 音を鳴らす | Web Audio。基音＋倍音を重ね、高い音ほど速く減衰させる |
| 鳴っている音符が光る | Verovio の timemap（時刻→音符ID）と SVG の要素IDを突き合わせ |
| **撮った楽譜を移調** | `omr.js` が五線と符頭を見つけ、移調後の位置を重ねて描く・鳴らす |

## omr.js — ブラウザ内で動く軽量OMR

このアプリが作った「まっすぐな白黒ページ」だけを相手にする、割り切った実装。

0. **先に傾きを直す**。四隅を指で合わせる以上1〜3度のズレは残り、幅1290pxで0.5度傾くだけで
   五線が1線間ぶんずれて「横の連なり」が消える。列ごとに縦へずらして黒画素の分布が
   いちばん尖る傾きを選ぶ（推定では縦方向を間引かないこと。細い線が丸ごと抜ける）
1. 長く途切れない横の連なりから五線を見つける（2段構え。2回目は既知の線間で検証）
2. 五線を2段ずつまとめて大譜表とみなす
3. 積分画像で符頭らしい塗りを総当たりで探す。横に長く続くもの（梁・加線）と
   縦に長く続くもの（音部記号・小節線・符尾）は除く
4. 五線からの高さで音の高さを決める

正解データでの実測（4通りの切り取り方で検証）:
**五線7〜8/8段・音高の再現率65〜92%・F1 60〜75%・約430〜510ms**。
傾き補正を入れる前は同じ4件が 0〜5段／再現率0〜64% だった。

## 動かないもの

**音の長さ（リズム）は読み取れない。** そのため移調した楽譜を組み直して印刷することはできない。
学習済みモデルを使うサーバ版（oemer）でも複雑な曲では74%しか合わない箇所で、
この方式では手が出ない（`docs/技術検証レポート_M0.md` 参照）。

移調タブの「お手本」は、パブリックドメインのモーツァルト K.545 冒頭8小節を事前に浄書したもの。

## ビルド

```bash
# 1. 移調デモのデータを作る（music21 + verovio が要る。../spike/README.md 参照）
python spike/build_demo.py          # → demo_data.json

# 2. テンプレートに流し込む
python build.py                     # → index.html
```

`index.template.html` が編集対象。`index.html` は生成物。
